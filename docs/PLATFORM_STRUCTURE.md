# CORE — структура платформы (хендофф для дизайнера)

> Документ описывает **текущую** структуру продукта: экраны, блоки, компоненты,
> токены, модель данных и поведение. Его можно целиком отдать дизайнеру
> (в том числе Claude) как бриф для нового дизайна — он содержит всё, что нужно,
> чтобы не сломать логику при смене визуала.
>
> Источник истины по коду: `src/` (фронтенд), `api/` (бэкенд), `tailwind.config.ts`
> + `src/index.css` (токены).

---

## 1. Что это за продукт

**CORE** — внутренняя кросс-платформенная канбан-платформа управления задачами
компании **IT-HONA** (аналог Trello, но со своей спецификой: отделы, загрузка
сотрудников, дни рождения, Telegram-уведомления).

| | |
|---|---|
| Аудитория | сотрудники компании, ~20 человек, закрытый доступ по логину |
| Язык интерфейса | русский (единственный) |
| Платформы | веб (этот репозиторий) + PWA; iOS/Android — следующий этап на том же API |
| Основная тема | **тёмная**; светлая поддержана полностью |
| Иерархия данных | Пространство → Доска (проект) → Список (колонка) → Карточка → {Чек-лист, Комментарии, Вложения} |

Не Trello-клон в мелочах: у карточки есть **код задачи** (`IT-123`), **таймер до
дедлайна**, **стикеры** (регулярность, секундомер, таймтрекинг, напоминание), а
у платформы — корпоративные разделы «Компания», «Команда», «Отчёты».

## 2. Технический каркас (важно для дизайна)

- **React 18 + TypeScript (strict)**, **Vite 5**, **Tailwind CSS 3.4** — вся
  дизайн-система живёт в токенах Tailwind + CSS-переменных.
- **@dnd-kit** — drag-and-drop (мышь, тач, клавиатура).
- **lucide-react** — иконки, линейные, `strokeWidth={2}`.
- **PWA** (`vite-plugin-pwa`), иконки в `public/`.
- Бэкенд: Node (`node:http`, без фреймворка) + PostgreSQL + Redis + MinIO,
  прокси **Caddy**; всё поднимается `docker-compose.yml`.
- Роутера **нет**: переключение экранов — локальный `useState` в `src/App.tsx`
  (`AppView`). URL не меняется. Это ограничение стоит учесть при редизайне
  (если дизайн предполагает deep-link — это отдельная задача разработки).

### Состояние приложения (провайдеры, `src/main.tsx`)

```
ThemeProvider          // тема dark/light → data-theme на <html>
└── NowProvider        // тикающее «сейчас» для таймеров дедлайна
    └── AuthGate       // экран входа/регистрации ИЛИ приложение
        └── BoardProvider  // reducer всей доски + автосохранение на сервер
            └── App
```

**Навигация в сайдбаре (порядок фиксирован):**

## 4. Каркас страницы и размеры

### Десктоп (≥1024px, `lg`)

```
┌────────────┬──────────────────────────────────────────────┐
│  Sidebar   │  TopBar (2 ряда)                             │
│  256px     ├──────────────────────────────────────────────┤
│  bg-sidebar│  main (скролл)                               │
│            │                                              │
└────────────┴──────────────────────────────────────────────┘
                                  + CardDetailDrawer 480px справа
```

| Элемент | Размер |
|---|---|
| Sidebar | `w-64` = **256px**, `border-r`, фон `--sidebar` |
| Мобильное меню (drawer слева) | 280px, максимум 85vw |
| Колонка доски | `300px` (на узких — `86vw`, максимум 320px) |
| Панель задачи (Drawer справа) | **480px**, `min(480px, 100vw)` |
| Контентный контейнер разделов | `max-w-container` = **1440px**, отступы 16/24px |
| Настройки — контейнер | 1080px |
| Нижняя таб-панель | высота ≥64px + safe-area, blur 12px |
| Отступы страницы | `px-4` (моб.) → `px-6` (≥sm) |

### Мобильный

Sidebar скрыт → бургер в шапке открывает `MobileNav`. Снизу — фиксированная
`MobileTabBar` (зоны нажатия ≥44px, учтён `env(safe-area-inset-bottom)`).
Контент получает `padding-bottom: 64px + safe-area`.

## 5. Экраны — детально

### 5.1 Вход / регистрация — `components/auth/LoginScreen.tsx`

Полноэкранный центрированный экран. Блоки:
- Лок-ап **CORE** (плитка со знаком + подпись «IT-HONA Platform»).
- Заголовок «Вход», подпись «Доступ только для команды».
- Поля: **Логин**, **Пароль**. Подсказка: «Создаётся из e-mail автоматически — можно изменить».
- Ссылка-подсказка про сброс пароля («обратитесь к администратору, раздел „Компания“»).
- Регистрация — по **коду из письма** на корпоративный домен (`ithona.tj`, `fazo-tech.tj`),
  логин генерируется транслитерацией e-mail (`src/lib/translit.ts`).

Три режима сервера: личные аккаунты / общий пароль на всех / открытый доступ.
Если бэкенд недоступен — экран входа **не показывается**, приложение работает локально.

### 5.2 Доска — `components/board/Board.tsx` + `Column.tsx` + `KanbanCard.tsx`

**TopBar, ряд 1:** бургер (моб.) · название доски (h3) · бейдж «Приватная» ·
поиск (44px→56px при фокусе) · стопка аватаров участников (до 4) ·
индикатор синхронизации (облачко: зелёное «сервер» / жёлтое «локально») ·
фон доски · уведомления · переключатель темы · кнопка **«Пригласить»**.

**TopBar, ряд 2:** сегментированный переключатель **Доска · Таймлайн · Таблица**
и быстрые фильтры-чипы: **Мои карточки**, **Просрочено** (активный чип — с галочкой).

**Колонка** (`bg-col`, radius 16):
- шапка: цветная точка стадии · название (двойной клик — переименовать) ·
  счётчик `N` или `N/лимит` · меню «⋮»;
- предупреждение WIP-лимита («Достигнут» — warning, «Превышен» — error, **не блокирует**);
- инлайн-композер «Добавить карточку» (вставка **вверх** списка);
- список карточек (вертикальный скролл), пустое состояние — пунктирный блок;
- меню колонки «⋮» (в этом порядке): **Переименовать** · **Сортировать по
  приоритету / по сроку / по названию** · **«Считать задачи выполненными»**
  (после включения — «Задачи выполнены ✓») · **Дублировать** ·
  **Переместить влево / вправо** (неактивны на краях) · **Цвет колонки**
  (палитра-свотчи) · **Удалить список** (danger).
- В конце ряда — пунктирный блок **«Добавить список»**.

**Канбан-карточка** (главный объект дизайна, `radius 16`, `bg-surface`, тень `card`):

```
│▌ IT-142   ⏱ 2д 04:30      🚩 Высокий      ← полоса-акцент слева (3px)
│  [метка] [метка]
│  Название задачи в две-три строки
│  ▓▓▓▓▓▓░░░░  60%
│  📅 21 июл   ☑ 3/5   💬 4   📎 2   [стикеры]  [+]   (аватары) [+]
```

- **Шапка:** код `IT-###` (моно) · таймер обратного отсчёта · флаг приоритета.
- **Цвет таймера и блока дедлайна задаётся СРОКОМ, а не приоритетом:**
  просрочено — `#EF4444`, ≤48ч — `#F59E0B`, иначе нейтральный.
- **Цвет левой полосы** — цвет **первой метки**; если меток нет — цвет стадии.
- Прогресс чек-листа показывается только если отмечен хотя бы один пункт.
- Нижний ряд виден **всегда** — в нём живут кнопки «+» (стикер и исполнитель).
- Стикеры-чипы: «каждую неделю» (brand), секундомер «00:00» (моно), таймтрекинг
  «N ч / M ч», напоминание «за 1 ч» (warning).
- Hover: подъём на 2px + усиление тени. Drag: наклон 2°, прозрачность оригинала 40%.

**Поповеры с доски** (`StickerMenu.tsx`): «Добавить стикер» (Исполнитель, Дедлайн,
Приоритет, Регулярная задача, Секундомер, Таймтрекинг, Напоминание) и «Исполнитель»
(поиск по имени/отделу, пустое состояние «Никого не найдено»).

**Фон доски** (`BoardBackgroundModal.tsx`): 10 градиентных пресетов (Изумруд,
Океан, Индиго, Закат, Слива, Роза, Бирюза, Ночь, Вишня, Аврора) + загрузка
своей картинки (сжимается до 1600px).

### 5.3 Таймлайн — `components/board/Timeline.tsx`

Гант-подобный вид: слева колонка названий **240px**, справа сетка дней по **34px**,
окно **−7 … +21 день**. Полоса задачи: от `startDate ?? createdAt` до `dueDate`,
цвет — цвет колонки, просроченные подсвечены. Карточки без срока не показываются
(есть счётчик скрытых).

### 5.4 Таблица — `components/board/TableView.tsx`

Колонки: **Код · Задача · Список · Приоритет · Срок · Чек-лист · Исполнители**.
Подчиняется тем же быстрым фильтрам.

### 5.5 Панель задачи — `components/board/CardDetailDrawer.tsx`

Правый Drawer 480px, оверлей `black/50`, анимация 260ms, закрытие по `Esc`.

**Шапка панели:** код задачи (моно) + пилюля с названием списка в цвете стадии.

**Секции сверху вниз** (каждая — `Field` с иконкой и подписью):

1. **Заголовок** — редактируемый инпут (h3), подсветка фона при фокусе.
2. **Приоритет** — выбор из четырёх.
3. **Срок** — свой пикер даты и времени (блоки «ЧАС» / «МИН»), под ним текст
   остатка («осталось N дн N ч» / «просрочено на N дн»).
4. **Список** — перенос карточки между колонками.
   *Срок и Список стоят в столбик, а не в две колонки: длинный текст «просрочено
   на N дн» не помещался в половину ширины.*
5. **Исполнители** — аватары назначенных + список свободных участников доски.
6. **Метки** — чипы палитры доски + добавление.
7. **Описание** — многострочное поле.
8. **Чек-лист** — «Название чек-листа…», пункты «Добавить пункт…», прогресс.
9. **Вложения** — имя, тип, размер + счётчик в подписи.
10. **Чат задачи** — комментарии + поле ввода и «Отправить», счётчик в подписи.

### 5.6 Дашборд — `components/dashboard/Dashboard.tsx`

Шапка: «Дашборд» + переключатель темы. Контент — 3 ряда:

- **Ряд 1 — 4 KPI-плитки** (2 колонки на моб., 4 на десктопе):
  Активные задачи (brand) · Просроченные (error) · Выполнено за неделю (success) ·
  Загрузка команды (warning). Каждая: иконка, подпись, крупное число, дельта, полоса.
- **Ряд 2 (1.55fr / 1fr):**
  «Скорость по отделам» — столбчатая диаграмма план/факт по отделам
  (высота зоны столбцов **фиксирована 132px**, подписи отдельной строкой под ней —
  иначе нулевые линии разъезжаются) + легенда «Закрыто / План».
  «Загрузка сотрудников» — аватар, имя, полоса, %. Цвет: ≥90% error, ≥70% warning, иначе brand.
- **Ряд 3 (1.55fr / 1fr):**
  «Ближайшие дедлайны» (до 5, клик открывает карточку; пусто — «Дедлайнов нет») +
  «Активность» (лента с меткой live).

### 5.7 Календарь — `components/calendar/Calendar.tsx`

Месячная сетка (Пн–Вс), переключение месяцев стрелками. В ячейке — карточки с
дедлайном на этот день (код, приоритет, просрочка) и **дни рождения** сотрудников
(иконка торта, «День рождения 🎂»). Справа/снизу — детали выбранного дня.

### 5.8 Команда — `components/team/Team.tsx`

Таблица-грид `2fr 1.3fr 1fr 0.7fr 0.7fr 1.4fr`:
**Сотрудник · Роль · Отдел · Активных · Просрочено · Загрузка**.
Роли: Администратор / Участник / Наблюдатель. Норма — **4 активные задачи** на человека,
загрузка = active/4 в процентах. Сортировка — по числу активных задач.

### 5.9 Компания — `components/company/Company.tsx` (самый большой экран, 901 строка)

Секции:
- **Проекты · N** — грид карточек проекта (1/2/3 колонки). В карточке: название,
  участники (стопка аватаров), меню: Открыть, Переименовать, Участники, Дублировать,
  Архивировать, Копировать ссылку, Удалить. Плюс инлайн-создание проекта.
- **Архив · N** — архивированные доски, восстановление.
- **Отделы · N** — управляемый справочник (влияет на диаграмму дашборда).
- **Сотрудники · N** — таблица Имя · Должность · Отдел; действия администратора:
  **Сбросить пароль** (модалка с новым паролем и копированием).
  Пустое состояние: «Пока никто не зарегистрировался.»
- **Дни рождения** — ближайшие, «Сегодня 🎂 / Завтра / через N дн.»
- **Telegram-уведомления** — статус «подключён», привязка/отвязка, deep-link на бота,
  подпись «Присылаю напоминания о днях рождения и дедлайнах».

### 5.10 Отчёты — `components/reports/Reports.tsx` *(без входа в меню)*

- Общая сводка: всего / выполнено / просрочено.
- Таблица по сотрудникам: **Сотрудник · Всего · В работе · Готово · Просроч.** + %.
- Блок просроченных задач (пусто — «Просроченных задач нет 🎉»).
- Дедлайны на ближайшую неделю (пусто — «На ближайшую неделю дедлайнов нет»).

### 5.11 Настройки — `components/settings/Settings.tsx`

Четыре карточки в колонке (максимум 1080px):

1. **Профиль** — аватар (загрузка/удаление, обрезка в квадрат 256px), имя,
   «Сменить пароль», «Сменить e-mail» (модалки), интеграция с Telegram,
   «Доступ по ссылке в мой профиль» (копирование инвайт-ссылки), «Выйти».
2. **Уведомления** — таблица `Событие · Включить событие · Звуковое уведомление ·
   Уведомление в браузере · Push в мобильном`, две группы: «Чаты задач» и
   «Личные и групповые чаты». Плюс «Скрывать системные сообщения в чате после просмотра».
3. **Внешний вид системы** — Цветовая схема (тёмная/светлая), Цветные полосы у колонок,
   Язык интерфейса, Фон досок («текущая» + «Сменить»).
4. **Компании** — список компаний/пространств.

## 8. Модель данных (`src/types.ts`)

```
AppData
├── workspace: { id, name, boards[] }
├── users: Record<id, User>          // name, initials, color, avatar?, department?, role?, online?
├── currentUserId
├── boards: Record<id, Board>        // name, visibility, listIds[], memberIds[], archived?, background?
├── boardOrder[] · activeBoardId
├── lists: Record<id, List>          // title, cardIds[], wipLimit?, color?, done?
├── cards: Record<id, Card>
├── labels: Record<id, Label>        // name, color
└── departments: string[]
```

**Card:** `title, description?, labelIds[], assigneeIds[], priority, dueDate?, startDate?,
checklists[], comments[], attachments[], createdAt, code?, stickers?, spent?, planned?`

- `priority`: `low | medium | high | critical`
- `stickers`: `{ repeat?, stopwatch?, tracking?, reminder? }`
- `code` — постоянный номер задачи, присваивается один раз (`IT-<code>`).
- Позиция карточки = **индекс в `list.cardIds`** (порядок хранится в списке).
- `list.done` — явный системный признак «задачи выполнены» (не входят в KPI,
  просрочки, загрузку). Название списка на логику **не влияет** — эвристика по
  названию осталась только для старых данных.
- `board.visibility`: `private | workspace | public`; роли: `observer | member | admin`.

## 10. Взаимодействие, состояния, доступность

- **DnD:** мышь — порог 6px (чтобы клик открывал карточку); тач — long-press 250ms
  (чтобы обычный свайп прокручивал колонку); клавиатура — через `KeyboardSensor`.
  Drag overlay: карточка наклонена на 2°, оригинал 40% прозрачности,
  drop-анимация 200ms.
- **Оптимистичное обновление:** перемещение применяется сразу, сохранение — фоном.
- **Индикатор режима:** `mode = loading | server | local`. В локальном режиме
  (сервер недоступен) показывается жёлтый `CloudOff` и подпись
  «изменения не сохраняются» — состояние обязательно нужно сохранить в новом дизайне.
- **Пустые состояния** уже есть у: колонки, дедлайнов, просрочек, сотрудников,
  поиска исполнителя, таймлайна (скрытые задачи без срока).
- **Клавиатура:** `Esc` закрывает Drawer/меню/мобильное меню; `Enter` — подтверждение
  во всех инлайн-полях; двойной клик — переименование колонки.
- **Доступность:** `aria-label` на всех иконочных кнопках, `role="dialog"`+`aria-modal`
  у Drawer и мобильного меню, видимый фокус, тач-зоны ≥44px.
- **Живые данные:** `NowProvider` тикает — таймеры обратного отсчёта на карточках
  обновляются сами; цвет меняется при переходе через 48ч и через дедлайн.

## 11. Бэкенд (контекст, на дизайн влияет слабо)

`api/server.js` — Node без фреймворка. Эндпоинты:

```
GET  /api/health
GET  /api/auth/me
POST /api/auth/register/request-code   POST /api/auth/register
POST /api/auth/login                   POST /api/auth/logout
POST /api/auth/change-password         POST /api/auth/profile      POST /api/auth/avatar

GET  /api/telegram/status              POST /api/telegram/link     POST /api/telegram/unlink
GET/PUT /api/board                     ← вся доска одним документом
```

Сессии — cookie `sid` (HttpOnly, 30 дней), пароли — scrypt + соль.

Реального времени (WebSocket) пока **нет** — presence в дизайне это статус `online`, не live-курсоры.

## 12. Бриф: что сохранить, что можно менять

### Обязательно сохранить (это логика, не украшение)

1. **Цвет дедлайна задаётся сроком, а не приоритетом** (просрочено → красный,
   ≤48ч → жёлтый). Приоритет — отдельный флажок.
2. **Левая полоса карточки = цвет первой метки**, а не приоритета.
3. **Нижний ряд карточки виден всегда** — там кнопки «+» (стикер, исполнитель).
   Прятать их в hover нельзя: на тач-устройствах hover'а нет.
4. **WIP-лимит предупреждает, но не блокирует.**
5. **Фиксированная высота зоны столбцов** в диаграмме «Скорость по отделам» —
   иначе многострочные подписи разъезжают нулевые линии и проценты врут.
6. Полная поддержка **обеих тем** через токены — ни один цвет не должен быть
   захардкожен мимо переменных.
7. Индикатор **локального режима** (сервер недоступен).
8. Тач-зоны ≥44px и safe-area на телефоне.

### Свободное поле для нового дизайна

- Ритм и плотность: сейчас интерфейс довольно плотный, шкала типографики
  используется не полностью (много «сырых» размеров вроде `13.5px`, `15px`, `17px`
  мимо токенов `small/body/h3`) — это стоит привести к системе.
- Иерархия внутри карточки: сейчас в нижнем ряду может накопиться до 8 элементов
  (дедлайн, чек-лист, комментарии, вложения, 4 стикера, «+») — карточка переполняется.
- Дашборд: KPI-дельты частично захардкожены демо-значениями (`+6 за неделю`, `+15%`) —
  дизайн должен предусмотреть состояние «данных пока нет».
- «Отчёты» нужно вернуть в навигацию (см. находку №1).
- Пустые состояния, состояния загрузки и ошибок сейчас минимальны.
- Мобильная версия доски: сейчас это те же колонки в горизонтальном скролле —
  есть простор для полноценного мобильного паттерна.
