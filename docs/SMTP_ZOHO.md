# Настройка почты Zoho для кодов подтверждения

Инструкция для регистрации по коду из письма. Всё делается один раз.

---

## Шаг 1. Определите свой центр данных Zoho

Настройки сервера зависят от того, где создан аккаунт. Самый надёжный способ —
посмотреть MX-записи домена в консоли Zoho (**Домены → ваш домен → MX**) либо
командой:

```bash
dig +short MX ithona.tj      # или: nslookup -type=MX ithona.tj
```

| MX-записи домена | Зона сервера |
|---|---|
| `mx.zoho.com`, `mx2.zoho.com` | `.com` |
| `mx.zoho.eu`, `mx2.zoho.eu` | `.eu` |
| `mx.zoho.in`, `mx2.zoho.in` | `.in` |
| `mx.zoho.com.au` | `.com.au` |
| `mx.zohocloud.ca` | `zohocloud.ca` |

Тот же признак виден по адресу, с которого вы входите в почту
(`mail.zoho.com` / `mail.zoho.eu` / …).

## Шаг 1б. Выберите сервер по тарифу — smtp или smtppro

Имя сервера зависит не только от зоны, но и от тарифа. Это вторая частая
причина ошибки «535 Authentication Failed»: подключение проходит, а логин
отвергается, потому что ящик обслуживается другим кластером.

| Какой у вас ящик | Сервер (зона `.com`) |
|---|---|
| Платный тариф организации, почта на своём домене (`you@ithona.tj`) | **`smtppro.zoho.com`** |
| Бесплатная организация или личный `@zohomail.com` | `smtp.zoho.com` |

Для других зон — по тому же правилу: `smtppro.zoho.eu`, `smtppro.zoho.in`
и так далее.

**Для ithona.tj:** MX указывают на `mx.zoho.com`, тариф Mail Lite платный,
почта на своём домене → сервер **`smtppro.zoho.com`**, порт 465, SSL.

## Шаг 2. Создайте пароль приложения

Обычный пароль от почты для сторонних программ не подходит (тем более при
включённой двухфакторной защите). Нужен отдельный пароль приложения:

1. Откройте `accounts.zoho.com` (или `.eu` / `.in` — тот же центр данных).
2. Раздел **Security** (Безопасность) → **App Passwords** (Пароли приложений).
3. **Generate New Password**, название — например `CORE`.
4. Скопируйте показанный пароль. **Он показывается один раз.**

Этот пароль вставляется в `SMTP_PASS`.

---

## Шаг 3. Проверьте, что доступ по SMTP включён

В Zoho Mail: **Настройки → Почтовые аккаунты → IMAP/SMTP** — доступ по SMTP
должен быть разрешён. В корпоративном тарифе это может быть закрыто
администратором в `mailadmin.zoho.com`.

> **Важно про бесплатный тариф Zoho.** Доступ по SMTP/IMAP для внешних
> приложений, как правило, доступен только на платных тарифах: на бесплатном
> почта работает лишь через веб и мобильное приложение. Признак — при попытке
> открыть настройки Zoho перебрасывает на страницу тарифов
> (`mode=redirectToPricing` в адресе). Тариф виден в `mailadmin.zoho.com` →
> **Subscription**. Если SMTP закрыт — см. следующий раздел.

---

## Если SMTP в Zoho недоступен

Приложению нужен **любой** SMTP-сервер, не обязательно тот же, где лежит почта.
Для кодов подтверждения объём крошечный (одно письмо на сотрудника при
регистрации), поэтому подойдёт бесплатный тариф любой службы рассылки.

| Вариант | Замечания |
|---|---|
| **ZeptoMail** (сервис Zoho) | Создан ровно для таких писем, остаётся в экосистеме Zoho, оплата по факту. Хост `smtp.zeptomail.com`, логин и пароль выдаются в консоли ZeptoMail |
| **Brevo**, **Resend**, **Mailgun**, **SendGrid** | Есть бесплатные тарифы, которых с запасом хватает на регистрацию 20 сотрудников |
| **Платный тариф Zoho Mail** | Открывает SMTP у существующих ящиков, ничего больше настраивать не нужно |
| **Оставить код-приглашение** | Ничего не настраивать: сотрудник получает код от администратора, как сейчас |

Настройка одинаковая при любом выборе — меняются только четыре значения
`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`; в коде приложения ничего
править не нужно.

Домен отправителя в `SMTP_FROM` у сторонних служб нужно подтвердить (они
попросят добавить DNS-записи SPF и DKIM для `ithona.tj`) — иначе письма будут
попадать в спам.

## Шаг 4. Впишите настройки в .env на сервере

```bash
cd /opt/ithona/app
nano .env
```

Добавьте (подставьте свой сервер из шага 1 и свой адрес):

```
SMTP_HOST=smtppro.zoho.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=noreply@ithona.tj
SMTP_PASS=пароль_приложения_из_шага_2
SMTP_FROM=CORE <noreply@ithona.tj>
```

Порт 465 (`SMTP_SECURE=true`) — самый надёжный вариант.
Если он закрыт у провайдера, используйте `SMTP_PORT=587` и `SMTP_SECURE=false`.

**Важно:** адрес в `SMTP_FROM` должен совпадать с `SMTP_USER` (или быть его
подтверждённым псевдонимом в Zoho). Иначе Zoho отклонит письмо.

Сохранить: `Ctrl+O`, `Enter`, выйти: `Ctrl+X`.

## Шаг 5. Примените и проверьте

```bash
docker compose up -d --build
docker compose exec api node send-test-mail.js ваш.адрес@ithona.tj
```

Скрипт покажет настройки (пароль не печатается), проверит подключение и
отправит тестовое письмо с кодом `123456`.

Ожидаемый результат:

```
[mail] SMTP smtppro.zoho.com:465 готов, отправитель: CORE <noreply@ithona.tj>
Готово: тестовое письмо с кодом 123456 отправлено на ваш.адрес@ithona.tj.
```

Письмо не пришло — посмотрите папку «Спам».

## Если не получилось

| Сообщение | Причина и что делать |
|---|---|
| `Invalid login` / `535 Authentication Failed` | 1) Для платного тарифа с почтой на своём домене сервер должен быть `smtppro.zoho.com`, а не `smtp.zoho.com` (шаг 1б). 2) Пароль приложения создан под другим пользователем — его нужно создавать, войдя именно как `SMTP_USER`. 3) Взят обычный пароль вместо пароля приложения |
| `getaddrinfo ENOTFOUND` | Неверный SMTP-сервер — проверьте центр данных (шаг 1) |
| `Connection timeout` | Порт закрыт. Попробуйте 587 с `SMTP_SECURE=false` |
| `Relaying disallowed` / `553` | `SMTP_FROM` не совпадает с `SMTP_USER` — приведите к одному адресу |
| `[mail] выключена (нет SMTP_HOST)` | Переменные не подхватились: проверьте, что правили `/opt/ithona/app/.env`, и выполните `docker compose up -d --build` |

Логи почты в любой момент:

```bash
docker compose logs api | grep mail
```

---

## Пока почта не настроена

Регистрация продолжает работать по коду-приглашению (`INVITE_CODE` в `.env`) —
система не остаётся без возможности зарегистрировать сотрудника. Как только
`SMTP_HOST` задан, форма сама переключается на код из письма.
