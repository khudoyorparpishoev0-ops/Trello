# ADR 0001 — HTTP-фреймворк: Fastify 5

- **Статус:** принято владельцем 23.09.2026 (решение D-1, Architecture v1.0 Final §0, §3).
- **Реализация:** Phase 1 — `apps/api`.

## Контекст

API v1 — один файл `api/server.js` на `node:http` с цепочкой `if`: без валидации схем, без слоя
авторизации, без типов (§1, §2 REBUILD). Для сотни маршрутов v2 с RBAC на каждом это не поддерживается.

## Решение

Новый API строится модульно на **Fastify 5** (`apps/api`), контракты — zod-схемы из `packages/shared`
через `fastify-type-provider-zod`; OpenAPI 3.1 генерируется из тех же схем (`@fastify/swagger`) и
коммитится в `docs/api/openapi.json`, расхождение ломает CI. `buildApp(config)` — одна фабрика для
сервера, тестов (`app.inject()`) и генерации OpenAPI.

## Последствия

- Валидация входа и формат ошибок §9.2 — единые для всех маршрутов; 500 не раскрывает деталей.
- Заголовки безопасности — `@fastify/helmet`; CSRF — проверка `Origin` на не-GET запросах (§14.3).
- Плагины для cookie, rate limit и WebSocket подключаются в своих фазах (2, 11), не раньше.
- `api/server.js` v1 дальше не развивается; полезная доменная логика переносится по §2.
