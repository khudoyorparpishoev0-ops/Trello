# CORE — платформа управления задачами IT-HONA

**CORE** — кросс-платформенная канбан-платформа управления задачами (аналог Trello) компании **IT-HONA**.
Этот репозиторий — **веб-версия** (первый этап). Мобильные приложения iOS/Android появятся позже
на общем бэкенде.

> Текущее состояние — **рабочий прототип канбан-доски**: колонки, карточки с drag-and-drop,
> детали карточки, фильтры. Данные пока живут **в памяти**, без бэкенда.

## Стек

- **React 18 + TypeScript** — строгий режим
- **Vite** — дев-сервер и сборка
- **Tailwind CSS** — вся дизайн-система в токенах (`tailwind.config.ts`)
- **@dnd-kit** — доступный drag-and-drop (указатель + клавиатура)
- **lucide-react** — иконки (контурные, 1.6px)

Выбор соответствует рекомендованному стеку из ТЗ (React / TypeScript, библиотека drag-and-drop,
стейт-менеджмент).

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
```

Прочие команды:

```bash
npm run build      # проверка типов (tsc) + продакшн-сборка (vite)
npm run preview    # предпросмотр собранной версии
npm run lint       # ESLint
npm run verify     # линтер + типы + модульные тесты + сборка
npm run test:e2e   # сценарии в браузере на собранном dist
npm run test:db    # запись доски на настоящем PostgreSQL (версии, права)
```

`test:db` нужна поднятая база (`TEST_DATABASE_URL`, по умолчанию
`postgres://ithona:test@127.0.0.1:5432/ithona_test`). Без неё тест не падает,
а сообщает, что пропущен.

## Возможности прототипа

- **Доска** с колонками **To Do / In Progress / Done** (списки можно добавлять, переименовывать, удалять).
- **Drag-and-drop** карточек внутри списка и между списками (оптимистичное обновление, drag overlay,
  поддержка клавиатуры).
- **Канбан-карточка** с полным составом: индикатор статуса, метки, заголовок,
  приоритет, дедлайн (с подсветкой «скоро» / «просрочено»), прогресс чек-листа, исполнители,
  счётчики комментариев и вложений.
- **Детали карточки** (боковая панель): редактирование заголовка/описания, приоритет, дедлайн,
  перенос между списками, исполнители, метки, чек-листы (отметка пунктов в реальном времени),
  вложения, комментарии.
- **Быстрые фильтры**: поиск, «Мои карточки», «Просрочено».
- **WIP-лимит** списка (предупреждение при превышении, без блокировки — по ТЗ §4.2).
- **Тёмная и светлая темы** (тёмная — основная), переключение по токенам.
- **Отдельная раскладка доски на телефоне**: ряд чипов-списков и одна колонка во всю
  ширину вместо горизонтального скролла колонок.

## Дизайн-система (брендбук IT-HONA, rev. 1.0)

Соблюдается строго. Все токены — единый источник правды во фронтенде:
`tailwind.config.ts` (тема) + `src/index.css` (переменные поверхностей и статусов).

| Токен | Значение | Где |
|---|---|---|
| Зелёный (акцент) | `#22A74E` (тёмная тема `#33C561`) | `--green`, `theme.colors.brand` |
| Зелёный ink (текст) | `#186B36` (тёмная `#7FBF95`) | `--green-ink`, `brand.ink` |
| Заливка кнопок | `#22A74E` (тёмная `#186B36`) | `--fill`, `brand.fill` |
| Сайдбар | `#0E3B21` — одинаково в обеих темах | `theme.colors.sidebar` |
| Страница | `#F5F7F5` / `#0B120E` | `--page` |
| Поверхность карточек | `#FFFFFF` / `#151E18` | `--surface` |
| Подложка, поля | `#F5F7F5` / `#101613` | `--mist` |
| Статусы (фон / ink) | Успех `#E0F1E6`/`#186B36` · Внимание `#FBF1DD`/`#7A5510` · Авария `#F7E3E1`/`#8E2A20` · Информация `#E2EAF9`/`#23539F` | `ok` `warn` `err` `info` |
| Шрифты | Manrope (интерфейс) + JetBrains Mono (служебный слой) | `index.html`, `theme.fontFamily` |
| Шкала | H1 30/35 · H3 19/24 · Body 16/25 · Caption 13/19 · Label 11/16 капслок | `theme.fontSize` |
| Радиусы | 0 (плашки, таблицы) · 2 (чипы, поля, аватары) · 4 (кнопки, карточки, модалки) | `theme.borderRadius` |
| Тени | Две экранные ступени | `--sh-1`, `--sh-2` |
| Сетка | 4 · 8 · 12 · 16 · 24 · 32 · 48 · 64 | spacing по умолчанию |
| Анимации | 150–200ms, ease-out | `theme.transition*`, `keyframes` |
| Иконки | Lucide, контур, 1.6px | `lucide-react` |

Правила палитры, зашитые в токены: насыщенный тон живёт только в точках-индикаторах,
полосах и графиках, текст берёт ink-тон того же статуса; белый текст на зелёном — от 14px;
«таблеток» и круглых аватаров нет, поэтому `rounded-pill` намеренно равен 2px.

Тематические цвета заданы CSS-переменными (`src/index.css`) и переключаются сменой
`data-theme` на `<html>` — так поддерживаются обе темы одним набором утилит.
Сайдбар остаётся тёмно-зелёным в обеих темах: так задано брендбуком.

## Структура

```
src/
├── main.tsx                  # входная точка, провайдеры
├── App.tsx                   # каркас: Sidebar + экран + Drawer
├── index.css                 # Tailwind + токены тем (dark/light)
├── types.ts                  # логическая модель данных (ТЗ §2)
├── data/seed.ts              # демо-данные доски (в памяти)
├── lib/
│   ├── utils.ts              # cn(), даты, таймеры, прогресс, коды задач
│   ├── design.ts             # приоритеты, палитра меток, цвета стадий
│   ├── backgrounds.ts        # фоны досок
│   └── useIsPhone.ts         # раскладка доски на телефоне
├── store/
│   ├── boardStore.tsx        # reducer + действия доски, сводки по проектам
│   ├── auth.tsx              # вход, регистрация, профиль
│   ├── theme.tsx             # контекст темы
│   └── now.tsx               # единое «сейчас» для таймеров
└── components/
    ├── ui/                   # примитивы дизайн-системы
    │   ├── Button, IconButton, Avatar, Badge, Priority,
    │   ├── ProgressBar, Checkbox, Toggle, Menu, Drawer, Logo
    ├── layout/               # Sidebar, ScreenHeader, TopBar, MobileNav, MobileTabBar
    ├── board/                # Board, Column, KanbanCard, CardDetailDrawer, Timeline, TableView
    ├── dashboard/ reports/ team/ company/ calendar/ settings/ auth/
```

Шапка контента у всех экранов одна — `layout/ScreenHeader`: крошки, заголовок,
подпись, поиск, участники, блок сервера, дата и кнопки. Раньше каждый экран рисовал
свою, отсюда расходились кегли заголовков.

## Модель данных

Иерархия по ТЗ логики §2: `Пространство → Доска → Список → Карточка → {Чек-лист, Комментарии, Вложения}`.
Состояние нормализовано (`lists`, `cards`, `labels`, `users` по id); позиция карточки — индекс в
`list.cardIds`. См. `src/types.ts`.

## Деплой на сервер

Боевой стек (один сервер, ~20 пользователей) поднимается через Docker Compose:
**Caddy** (обратный прокси + авто-HTTPS) → фронтенд (nginx со статикой) + заготовка **API** +
**PostgreSQL** + **Redis** + **MinIO** (вложения). Наружу открыт только Caddy (80/443).

- Пошаговая инструкция подготовки сервера (Ubuntu, безопасность, Docker, HTTPS, бэкапы):
  **[`deploy/RUNBOOK.md`](deploy/RUNBOOK.md)**
- Оркестрация: `docker-compose.yml` · прокси: `deploy/Caddyfile` · секреты: `.env.example` → `.env`
- Ежедневный бэкап БД: `deploy/backup.sh` (cron)

Кратко:

```bash
cp .env.example .env      # заполнить пароли; домена нет → SITE_ADDRESS=:80
docker compose up -d --build
curl http://localhost/api/health   # проверка связи стека
```

Когда появится домен — в `.env` вписать `SITE_ADDRESS=board.example.com`, и Caddy сам выпустит HTTPS.
